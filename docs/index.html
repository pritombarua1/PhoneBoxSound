How it works

One capture, many phones, one moment

Why the phones stay together

Packets reach each phone at a different time: Wi-Fi is uneven. So a phone never plays audio "when it arrives". Every 10 ms block carries the moment it was captured, and every phone plays it at the same agreed moment: capture time + sync buffer.

Blocks arrive early, late, in between; all three turn white (play) on the same line.

The four mechanisms

  1. Shared clock. Each phone pings the PC and keeps only recent, fast round trips to learn the PC's clock. If new measurements disagree (the browser was asleep), old ones are thrown away at once.
  2. Scheduled playback. Blocks are queued on the phone's audio hardware clock for an exact sample, not "as soon as possible".
  3. Drift correction. Tiny errors are absorbed by playing up to 0.4% faster or slower: inaudible, no clicks.
  4. Adaptive buffer. Each phone reports how much buffer its Wi-Fi really needs; the PC uses the largest, raises it instantly on trouble and lowers it gently.

Permissions and settings

What each permission allows

PermissionAt firstThe phone can
SpeakerOnPlays the PC's sound on this phone, in sync with the others.
Media remoteOnPlay, pause, skip, seek and volume of what is playing; see the queue; share its link.
IntercomOnTalk to the other phones and the PC, and hear announcements.
Search and playOnSearch YouTube, Spotify and Apple Music and start a result on the PC.
Keyboard & mouseOffMove the PC's pointer, click, scroll and type: full control of whatever is on screen.
ClipboardOffRead what you copied on the PC, and put text or pictures on the PC's clipboard.
Screen viewOffSee the PC's screen (or the active window) live on the phone.
PowerOffLock, sleep, restart or shut down the PC, each after a confirmation and a countdown.
Manage speakersOffChange every phone's volume, channel and timing, pause all, start the bedtime timer.
FilesOffSend files to the PC's share folder and download what is in it. Nothing outside that folder.
PC commandsOffPress the command buttons you made in Settings. A phone can never create or change one.
Host musicOffPlay audio files from this phone on every phone, in place of the PC's sound.
Approve phonesOffLet a waiting phone in, or turn it away, without going to the PC.
Shake to lock downOffThree firm shakes of this phone put the PC into lockdown.

Everything marked Off reaches into the PC itself. It stays off until you switch it on for that phone, is withheld from a phone that has not proved its own key while strict security is on, and from every phone during lockdown.

Safety

PairingThe 4-digit code only reaches the waiting room: you approve each new phone. Five wrong codes lock that address out for a minute. The code can never take over a phone that is already paired.
IdentityOn the secure link each phone holds a key that can't be copied off it and signs in with it. A stolen id or token is refused.
LockdownOne button: every phone keeps playing, none can control the PC, nobody new can join.
StoragePassword-protected and encrypted. A changed, swapped or missing file stops the server from starting.
RolesSpeaker, media remote, intercom, and eight that reach into the PC itself and stay off until you enable them: keyboard & mouse, clipboard, screen view, power, managing all speakers, files, commands, hosting music. A phone can also be blocked outright.
DashboardOnly this PC, and only with the password (or the API token). Phones can't download its code. Other websites are refused, pages can't be framed or injected into.
NetworkEverything stays on your local network. Player web interfaces are bound to this PC only.

Under the hood

Architecture

Server · Python

audio.pyWASAPI loopback capture, timestamps, packet format
hub.pyDevices, pairing, routing, adaptive buffer, intercom, zones, scenes
media.py, players.pyFinds what is playing and controls it
snap.py, desktop.pyVideo frame for artwork; clipboard and screen view
calibrate.pyChirp detection: aligns phones through the PC microphone
app.pyHTTP/HTTPS, WebSockets, REST API

Web app · React + TypeScript + Vite

web/src/playerPhone app. engine.ts does sync and playback outside React, so 100 packets a second never wait for a render
web/src/controlDashboard; each page is a lazy-loaded chunk
web/src/libClock sync, wire format, intercom audio, UI kit, tiny store

Builds are content-hashed, so phones always load the current version.

npm install          # once
npm run setup        # once: Python dependencies
npm run dev          # server + live-reloading UI  →  http://localhost:5173/control
npm run build        # production build into web/dist
npm start            # build, then run            →  http://localhost:8080/control
npm run docs         # regenerate these screenshots, videos and the PDF (also an end-to-end test)
